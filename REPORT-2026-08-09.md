# Report — 2026-08-09: the reduced-motion misdiagnosis, the bottom chrome, and an audit pass

Branch `corkboard-realism`, tip `3ff676e`. Staging `main` rebuilt at `1df2d57`
and verified live. Production (`whittworks-site` / whittworkstudios.com) was
not touched.

---

## TL;DR — everything done, and whether it matters

**1. Diagnosed the "scroll animation is broken" report. It was not broken.**
Windows animation effects are off on the new machine, so Chrome reports
`prefers-reduced-motion: reduce`, and `js/board.js` has always answered that by
snapping to the nearest camera stop instead of interpolating.
*Matters:* yes, but not as a bug — as a design failure. Nothing was wrong with
the code and nothing needed fixing in the camera.

**2. Proved it three independent ways rather than asserting it.**
OS flag (`SPI_GETCLIENTAREAANIMATION` → false), the browser
(`matchMedia("(prefers-reduced-motion: reduce)").matches === true` in real
Chrome), and the camera itself — 14 distinct transforms across 15 scroll
samples under `no-preference` versus 7 under `reduce`.
*Matters:* yes. The first two are circumstantial; the third is the camera
demonstrating it interpolates perfectly when allowed to.

**3. Added a motion toggle that overrides the OS in both directions.**
Session-scoped, keyboard-operable, `aria-pressed` reflects state, stops
following OS changes once used.
*Matters:* yes — this is the actual fix. The site's own author read hard cuts
as a defect within seconds; a visitor has less context and concludes the site
is broken. The OS preference stays the default because that part was correct.

**4. Enlarged the scroll instruction from 0.65rem to 1.05rem** (10px → 16.8px
measured) on a near-opaque plate, and removed its `aria-hidden`.
*Matters:* yes. It was smaller than every other word on the page while being
the only thing that explains the interaction, and screen-reader users were
never given it at all.

**5. Retimed the hint to fade on camera progress instead of pixels.**
Was `scrollY > 40% of one viewport`; now it holds until the camera has passed
stop 1, and returns if you scroll back up.
*Matters:* yes, and arguably more than the size change. The old trigger
retired the instruction before the first camera move had finished — it
disappeared exactly when it was still being read.

**6. Fixed an HTML comment I had just broken** — a closing `-->` with no
opening `<!--`, which parsed 642 characters of prose as visible body text in
every render mode.
*Matters:* yes. It was invisible in screenshots and caught only by the
innerText tripwires. This is the clearest argument for keeping them.

**7. Gated the `cork.webp` preload behind 901px.** Measured at 390×844:
cork requests 1 → 0, total requests 60 → 18.
*Matters:* moderately. Every phone was downloading 304KB of cork texture to
render the editorial design, which never paints it. This was the last open
item from the earlier tape-preload work.

**8. Added a Content-Security-Policy meta tag.**
*Matters:* little today, more later. There is no injection path on this site —
no user input, no forms, no network calls, nothing third-party, and no
`innerHTML`/`eval`/`document.write` anywhere. It is defence in depth for a
future that has one.

**9. Extended CSS motion suppression to cover `animation`, not just
`transition`, and scoped it so the toggle steers the stylesheet too.**
*Matters:* still yes, but less than when it was written — see item 14. The
arrow animation it was protecting reduced-motion visitors from has since been
removed outright, so the `animation` clause now guards nothing on this page
and everything a future one adds.

**10. Committed `tools/verify/cdp.mjs`,** the headless-Chrome harness. Node 24+,
zero dependencies, five checks.
*Matters:* yes, for future sessions. Every prior session rebuilt this by hand,
and the project's notes record two occasions where ad-hoc probes produced
false conclusions.

**11. Added `.gitattributes`** to stop LF/CRLF churn now that the project is
worked from both macOS and Windows.
*Matters:* only to diff readability, but the failure mode is a one-line change
buried in a thousand-line rewrite.

**12. Re-baselined the innerText tripwires** to 1505 / 1807 / 1474 / 1791 and
recorded the arc in `HANDOFF.md` and `GOALS.md`. Also corrected HANDOFF's
stale "board.js at ?v=16" — the tree was already at 17.
*Matters:* yes. Stale tripwires are worse than none, because the next session
trusts them.

**13. Deployed.** Branch pushed, staging rebuilt with both per-rebuild fixups
(CNAME deleted, noindex meta present), live-verified through headless Chrome.
Rollback point recorded: previous staging was `637c77a`.

**14. Removed the hint's arrow animation, same day it shipped, after the owner
reported new grit between stops.** `document.getAnimations()` showed
`hint-nudge` in state `running` at every scroll position tested — including
after the cluster had faded to `opacity: 0`. An `infinite` compositor
animation on a fixed layer above a board that is transformed every frame,
running the whole session, for an arrow nobody could see. `.board-chrome.faded`
also gained `visibility: hidden`, so the invisible cluster leaves compositing
entirely.
*Matters:* yes, and it was self-inflicted — a regression introduced and
removed within the same arc. Verified: zero animations at fractions 0 / 0.5 /
0.95.

**15. Shipped the warming class.** `html.warming` is set by the inline head
script beside `board-first`; `css/style.css` hangs the same collapsed shadow
filters off it that `.moving` uses; `js/board.js` removes it `MOVE_SETTLE`
after the load event. The board's first rasterisation is the most expensive it
ever does — cold tiles, `cork.webp` possibly still decoding, and shadow stacks
already measured at 173ms of a ~200ms frame — and tiles that miss that budget
draw nothing, which is the "chunks". It is set in the head and not in
`board.js` because `board.js` runs at the end of `<body>`, after the first
tiles have already rasterised at full cost.
*Matters:* yes. This is the lever identified during the original chunk work
and left unshipped, and it targets the load-time chunking directly. Verified
on live staging by polling a cold load: `warming` true with **1** drop-shadow
at `readyState: "loading"`, still 1 through load, then false with **4**
restored once settled.

Final state: branch `f22f923`, staging `4ace0b9`, both verified live.

## Examined and deliberately left alone

- **`MOVE_SETTLE = 600` and the `.moving` shadow collapse.** Both carry
  measured defences — a GPU trace showing a 428ms blocked task and a p95 table
  comparing 160 against 600. The standing rule for this pass was that defended
  code only changes on evidence at least as strong. I did not produce a
  competing measurement, so I did not touch them.
- **The four Rawpixel stickies, the two system-font arrows.** Documented,
  owner-decided, recorded in `SOURCES.md`.
- **`caden.jpg`'s blown-white background, the short red string near sticky 1,
  the caption arrow on its own line, reading mode's typed lines sitting off
  the ruled lines.** Owner-accepted residuals. The caption arrow is visible in
  the stop-4 capture; it remains a taste call, not a defect.
- **Duplicate top-level selectors** (`.board`, `.pc-head`, `.sticky-title`,
  `.typed`). Checked; they are base rules plus variants, not accidental
  overrides.
- **`STOPS[0]` and its `--first-frame` mirror in the head script.** Confirmed
  still in agreement. Not changed.

## Known gaps in this pass, stated plainly

- **The CSS audit was targeted, not exhaustive.** I read and reasoned about
  the regions I touched (the hint, the reduced-motion block, the design gates,
  the underlay rule) and ran a duplicate-selector scan across `style.css`. I
  did not read all 1,568 lines of `style.css`, nor `editorial.css` (466) or
  `reading.css` (326) line by line. The plan claimed I would; I am recording
  that I did not rather than implying coverage I don't have.
- **Clickjacking protection is not available on this host.**
  `frame-ancestors` cannot be carried by a meta CSP and meta `X-Frame-Options`
  is ignored by browsers. GitHub Pages cannot set response headers. This needs
  a different host to solve, and is recorded rather than fixed.
- **`'unsafe-inline'` is in the CSP** for both script and style. Hashing the
  inline head script was rejected because that script changes often and a
  stale hash would silently block it and hand every wide visitor the editorial
  design. Deliberate trade, not an oversight.
- **No screen-reader has actually listened to this page.** The accessibility
  work here was driven programmatically. That remains an open item from the
  previous handoff.
- **One machine only.** Everything was verified on this Windows box and in
  headless Chrome. The original dark-chunk report came from the owner's
  hardware, and nothing here re-tests that.
