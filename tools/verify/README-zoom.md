## Zoom frame-time profiler

Run `node tools/verify/zoom-profile.mjs [runs=5] [--zone=2] [--cpu-throttle=1] [--software]` to load the board in headless Chrome at 1440x900 (2x), click a paper with a real mouse event to zoom in, press Escape to zoom out, and print worst frame, p95 and frames over 20 ms for each direction plus the median across runs. It always exits 0, so read the numbers yourself; the documented 2026-08-24 result is a worst frame of about 18.6 ms each way with the GPU on, and `--software` launches Chrome with `--disable-gpu` while `--cpu-throttle=4` slows the CPU fourfold. Frame times come from CDP Tracing (the `devtools.timeline` and frame categories), using the end time of every presented compositor frame, because that is the interval a viewer actually sees and it does not depend on the page's main thread staying free. If a trace catches too few frames it falls back to a `requestAnimationFrame` delta sampler and says so in the summary, and `--method=raf` forces the sampler. Results move with machine load, so check `uptime` first and compare runs only from the same quiet machine.
